# 03. 귀속 — Risk 우선, 그 다음 파이

순서: **① 데스마다 Risk 산출 → ② 클러스터 잔여로 C·D 파이 → ③ 선수 배분(`spec/04`) → ④ 드리프트 귀속**

## 3.1 Risk — 데스 단위 한계 비용

```
각 데스 d (시각 t_d, 피해자 i):
  x_before = x(t_d⁻)
  x_death  = x_before 에서 "그 데스가 바꾼 것만" 반영
             (생존 인원 −1, 부활 잔여 + respawn_timer, 상대 골드 + 현상금)
  Risk_i  += G(x_death) − G(x_before)          # 항상 ≤ 0
```

- 데스는 **교전 결과와 무관하게 항상 본인 비용**이다 (퍼포먼스 지표 원칙). 이긴 교전 속의 데스도 개인에게 보인다.
- 부활 공백의 기대 비용은 부활 잔여 피처의 계수가 데스 시점에 한 번에 가격을 매긴다 — **"데스~부활" 시간창을 쓰지 않는다** (이중 기입 방지).
- **희생 데스**: 데스 비용은 그대로 받되, 같은 교전에서 본인 관여로 C·D 지분을 함께 받는다. 팀이 크게 이겼으면 상쇄, 아니면 순손실.
- **처형** = `champion_kill` 중 `killerID = 0`(포탑·미니언·중립 처치)은 Risk를 같은 방식으로 산출하고 배분 입력에서는 제외 (결정 26).
  `champion_kill_special`은 처형이 아니라 멀티킬·에이스·퍼스트블러드 **알림**이다 (같은 데스가 `champion_kill`에 이미 있음) — 씨앗·데스 어디에도 쓰지 않는다.
- 현상금 = `bounty + shutdownBounty` (킬러 골드). 어시스트 골드는 x_death에 넣지 않는다 (이후 클러스터 ΔG에 실현 골드로 들어감).
- `respawn_timer` = 데스 이후 피해자가 처음 사망 상태로 관측된 틱의 값.

## 3.2 클러스터 파이

**속도형 (결정 27, 2026-11-01)**: G = 현재 골드 + V (V = 앞으로 10분 기대 수입 = 골드를 버는 속도).
골드는 게임 구조상 누구나 계속 쌓이므로, 교전 성과는 **속도의 변화**(가속·감속, 스노우볼)로 잰다.

```
실현_us  = Σ_i [total_gold_i(e) − total_gold_i(s)]       # 클러스터 동안 번 골드 → 번 선수 본인 C (배분 없음)
ΔV_us    = ΔG_us − 실현_us                              # 속도 변화
시간항   = β_t·Δt + β_t²·Δ(t²)                         (클러스터 [s, e] 구간)
감쇠항   = Σ_f β_f · (틱 간 감소분: 부활 대기·바론·장로 버프 잔여 / 증가분: 생존 인원)   # 결정적 감쇠 (결정 28)
잔여_us  = ΔV_us − Σ Risk_d(클러스터 내 자팀 데스) − 시간항_us − 감쇠항_us
C 파이   = max(잔여_us, 0)                              # 가속
팀 계정 += min(잔여_us, 0) + 시간항_us + 감쇠항_us
           # 데스 비용을 빼고도 남는 감속 = 상대의 정상 획득 → 개인 무귀속
D 파이   = max(−잔여_opp, 0)                            # 상대 감속
```

원칙: **"상대가 잘한 것은 내 감점이 아니되, 내 데스는 항상 내 비용."**

- 이전 정의(잔여 = ΔG − Risk − 시간항)는 클러스터 동안의 평소 수입이 파이에 남아 D/C 중앙값 0.003(D = 0인 클러스터 94%)이 됐고, C 파이의 대부분이 평소 수입(그중 23%는 교전 비관여 선수가 번 골드)을 관여 비율로 나눈 값이었다 → `specs/step3_timeline_report_2026-11-01.md`. 이전 정의는 Step 5–6에서 **비교 기준선**으로 함께 산출한다.
- **결정적 감쇠 (결정 28)**: 사건 가치는 사건 순간에 매긴다 (데스 → Risk, 바론·장로 → 처치 순간 버프 잔여 × 단가). 이후 시간만으로 일어나는 감쇠(부활 대기·버프의 초당 감소, 부활로 생존 +1)는 누구에게도 귀속하지 않고 팀 계정으로 — 드리프트에서와 같은 처리. 빼지 않으면 데스 직후 부활 타이머 회복이 데스 팀의 C로 잡힌다 (순수 패배 클러스터의 66%).
- 상대 데스로 생긴 상대 감속은 상대 선수의 Risk이며 우리 D에 넣지 않는다 (킬러 몫은 현상금 → 실현 골드와 우리 가속 C). Step 6 결과로 재검토.

## 3.3 파이 배분

```
C_i = C 파이 × w_i / Σw
D_i = D 파이 × w_i / Σw
Σw = 0 이면: C 파이 → 팀 계정,  D 파이 → D_unattributed (팀 계정과 섞지 않음)
```

`w_i` 는 `spec/04-allocation.md`. 정규화 배분이므로 **어떤 w를 써도 파이 총량과 항등식은 불변**이다.

**D 처리 규칙**
1. Σw = 0 → `D_unattributed`로 별도 집계 (팀 계정은 자팀 항등식 구성요소, D는 그 밖이므로 섞지 않는다)
2. 우리 관여가 있는 클러스터(Σw > 0)에서만 D 배분 — 상대 자멸 흡수 방지
3. 양 팀 대칭 계산 — 같은 클러스터에서 team100·team200의 D를 각각. `ΔG_opp > 0`이면 D 파이 = 0

## 3.4 드리프트 귀속

```
C_i     += total_gold_i(b) − total_gold_i(a)          # 개인 실현 골드 그대로 (배분 없음, 클러스터 구간도 같음 — §3.2)
팀 계정 += ΔG_us(구간) − Σ_i [total_gold_i(b) − total_gold_i(a)]   # = G 예측 오차 성분
```

## 3.5 절대 금지

1. **현상금·prior 값을 C/D/Risk에 직접 더하지 않는다** — 실현 골드는 이미 ΔG 안에 있다 (이중계상).
2. **자팀 보존 항등식에 D를 넣지 않는다** — 상대 장부다 (프로토타입에서 혼입 시 −7.6k 오염 재현).
