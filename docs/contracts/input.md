# 입력 계약 — raw에서 필요한 것

## 1. 필수 필드

Step 0에서 아래 필드의 존재 여부·적재율을 **월별·대회별**로 리포트한다.

| 단위 | 필수 필드 | 쓰이는 곳 |
|---|---|---|
| 프레임·참가자 | 게임 시각, 참가자 ID, 팀(진영), 누적 획득 골드, 레벨, 생존 여부, 부활 잔여, 체력·최대 체력, **좌표(x, z)**, **누적 챔피언 대상 피해** | G 상태, 드리프트 C, 흡수, 존재, 딜 |
| 챔피언 킬 | 시각, 킬러, 피해자, 어시스트 목록, 현상금, 좌표 | 씨앗, Risk, 어시 |
| 에픽 몬스터 | 시각, 처치 팀, 몬스터 종류(드래곤 속성·장로 구분), 좌표 | 씨앗, 상태 |
| 건물 | 시각, 파괴된 쪽, 건물 종류·티어·라인, 좌표 | 씨앗, 상태 |
| 와드 | `spec/06-data-prep.md` §2 | 시야 2종 |
| 메타 | **게임 ID, 경기(match) ID, 경기 내 게임 번호(1~5), 대회, Split, 패치, 날짜, 블루·레드 팀, 승리 팀** | 분할·집계·승패 |
| 선수 | 선수 고유 ID, 표시 이름, 소속 팀, 포지션 | 집계 키 |

참고 — 이전 자체 수집본(Riot LiveStats 형식)에서 확인된 형태: 프레임은 `schema_type=gameStat`의 `participants[]`
(`participantID`, `teamID`, `totalGold`, `level`, `respawnTimer`, `playerName`, `championName`),
이벤트는 `schema_type=matchEvent`의 `rfc461Schema` (`champion_kill`, `epic_monster_kill`, `building_destroyed`,
`turret_plate_destroyed`, `champion_kill_special` — 2026 raw에서는 멀티킬·에이스 알림, 결정 26). `deathRecap`은 `list[{source, casterId, breakdown[]}]` 구조.
2026 raw의 형식은 Step 0에서 확인한다.

## 2. 상태 피처 확정 목록 — 우리 관점 x(t, side)

| # | 피처 | 정의 |
|---|---|---|
| 1–2 | 시간 | t(분), t² — **이 두 항의 기여 합이 "시간 항"** |
| 3–4 | 팀 골드 | 우리 누적, 상대 누적 |
| 5 | 레벨차 | Σ레벨(우리) − Σ레벨(상대) |
| 6–11 | 타워 | 티어별(외곽·2차·억제기 타워) 파괴 수 — 우리가 부순 것 3, 잃은 것 3 |
| 12–13 | 억제기 | 현재 파괴 상태 수(리스폰 반영) — 상대, 우리 |
| 14–15 | 넥서스 타워 | 파괴 수 — 상대, 우리 |
| 16–19 | 드래곤 | 스택(장로 제외) 우리·상대, 영혼 보유 우리·상대 |
| 20–23 | 버프 잔여(초) | 바론 우리·상대 (처치 후 180초), 장로 우리·상대 (처치 후 150초) |
| 24–25 | 생존 인원 | 우리, 상대 |
| 26–27 | 부활 잔여 합(초) | 우리, 상대 |
| 28–29 | 공허 유충 (`VoidGrub`) | 처치 수 우리·상대 |
| 30–31 | 전령·아타칸 | 처치 여부 우리·상대 (패치에 없으면 0) |
| 32 | 진영 | 블루 = 1 |
| — | 패치·대회 더미 | 학습 시 포함. 게임 중 불변이라 ΔG에는 영향 없음 |

**관점 반전(G_opp)**: 우리↔상대 쌍을 서로 바꾸고, 레벨차 부호 반전, 진영 반전.
**대칭 학습**: 같은 시점을 양 팀 관점으로 2행 생성.
